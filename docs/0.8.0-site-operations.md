# Bounded site operations in 0.8.0

These first-party MCP tools extend existing WordPress APIs. They introduce no
tables, field builder, arbitrary command execution, theme-file editing, or new
global permission settings. All calls retain connection scopes, role policy,
WordPress capabilities, access lockdown, and the ordinary audit boundary.

## Tool contracts

| Public MCP tool | Required inputs | Permission and behavior |
| --- | --- | --- |
| `navigation_read_item` | `menu_id`, `item_id` | `edit_theme_options`; existing classic item and menu-wide `expected_state`. |
| `navigation_update_item` | Same IDs, `expected_state`, `changes` | Confirmed existing-item update; label, custom-link URL, parent, order, target, rel only. |
| `content_fields_list_fields` | `post_id` | Editable REST-enabled public post type supporting custom fields; permitted scalar schemas only. |
| `content_fields_read_field` | `post_id`, `key` | Post read/edit and `edit_post_meta` permission; returns typed value, existence and `expected_state`. |
| `content_fields_update_field` | Same target, `expected_state`, `value` | Confirmed update of one existing scalar row through native metadata APIs. |
| `site_inspect_rendered_page` | `post_id` | Readable public, non-password-protected post; bounded anonymous permalink fetch. |
| `maintenance_clean_post_cache` | `post_id` | `manage_options` and `edit_post`; confirmed native post-cache invalidation request. |
| `maintenance_flush_rewrite_rules` | None | `manage_options`; confirmed current-site soft rewrite flush request after `wp_loaded`. |
| `integrity_check_core` | Optional `page`, `per_page` | `update_core`; super administrator on multisite; stable installed core/locale checksums. |
| `integrity_check_plugin` | Exact installed `plugin` basename; optional pagination | `update_plugins`; super administrator on multisite; matching WordPress.org manifest only. |

Reads require `content:read`; writes require `content:draft`. All four new write
tools require an exact-operation confirmation token, including trusted write
connections. `dry_run: true` validates and previews without changing target
data. The gateway binds confirmation and optional `idempotency_key` to the
actor, tool and payload. Supply the returned token with the unchanged operation;
use a new idempotency key for a new operation.

## Navigation boundary

The existing read-only classic/block inventory remains available. Only existing
classic items can be changed; creation, deletion, location reassignment, block
navigation rewriting and arbitrary item metadata are unsupported. Menus are
limited to 500 items and parent chains to 100 items. URL changes accept only
custom HTTP/HTTPS, root-relative or fragment links, never executable protocols,
credentials or protocol-relative URLs. Object-linked URLs cannot be overridden.

`navigation_read_item` returns a menu-wide state hash. The update validates it,
preserves native item fields, and verifies readback. Unchanged requests do not
invoke native writes. A failed partial update attempts one native restoration;
an unverifiable restoration returns terminal `partial_write`, which the gateway
must not automatically retry. The state check is optimistic, not a database
transaction, and cannot undo arbitrary third-party hook side effects.

## Registered fields boundary

Fields must be registered, single-valued, REST-exposed and editable under their
effective REST schema. Supported types are string, integer, number and boolean.
Protected keys, underscore-prefixed keys, serialized values, multiple rows,
unregistered fields, and complex field definitions are excluded. A registry over
1,000 entries fails closed. Listing is capped at 50 per page; text values at
4,000 UTF-8 bytes. The schema includes the native key and its REST alias.

Reads require both post read/edit access and field-specific metadata permission.
Registered defaults do not imply stored rows: missing fields report
`exists: false` and cannot be created by this tool. Writes honor native and REST
sanitization/validation, compare prior state, and verify persistence. Native
metadata APIs provide optimistic, not transactional, concurrency; ambiguous
outcomes are terminal `partial_write` with manual-inspection guidance. No generic
options access, field-definition editing, repeater or relationship writes are
provided.

## Inspection and maintenance boundary

Page inspection accepts a post ID, not a client-supplied URL. Its filtered
permalink must have the configured home origin; WordPress's safe HTTP client
adds URL validation. Requests carry no actor cookies or authorization headers,
follow no redirects, use a five-second timeout and cap HTML at 512 KiB. An
HTTP 200 HTML response is required. PHP DOM support is required for extraction.

The response contains bounded title, description, robots, canonical URL, and up
to 50 headings and 50 links. Scripts, styles, forms, templates and noscript
content are removed. Returned page text is untrusted evidence, not instructions.
It does not prove JavaScript rendering, computed styles, visual layout or draft
previews. Hosts that block loopback requests return an explicit fetch failure.

Cache maintenance calls native post-cache invalidation, including related core
cache bookkeeping. It does not call a global object-cache flush or claim to purge
CDNs or page-cache plugins. Suspended invalidation is an explicit error. Rewrite
maintenance requests a soft flush only, without changing permalink settings,
requesting server-file writes, or switching sites. These void native APIs return
request acknowledgements, not a guarantee about external caching or third-party
hook effects. Caches regenerate on demand; route-registration issues must be
corrected before rebuilding rewrite rules again.

## Integrity boundary

Official checksum requests use HTTPS with verification, no redirects, a
five-second timeout and a 1 MiB response limit. Core sends installed version and
locale; the selected plugin sends slug and installed version. No file content or
local filesystem paths are transmitted. External plugin update identities and
missing manifests are unsupported, not successful verification.

At most 20,000 manifest entries are accepted, and each call checks at most 50
files. Local reads are capped at 5 MiB per file and 25 MiB per call. Unsafe paths,
symlinks and non-regular files are rejected or explicitly skipped. Core excludes
`wp-content` and configuration files. Results identify only relative paths and
`matches`, `modified`, `missing` or an explicit unreadable/skipped outcome.

Results cover only that page's manifest-listed files. Compare `manifest_state`
while paging; restart if it changes. There is no unknown-file scan, malware
verdict, repair, deletion, or whole-installation pass. Changes by local filesystem
writers during a scan can affect the observed result.

## Validation and rollback

The canonical `composer test` includes the new focused PHPStan lane. Focused
tests cover schemas, discovery permissions, hostile values, stale state,
preview/no-op behavior, native failures, terminal partial writes, confirmation
and replay, anonymous HTTP limits, Unicode extraction and local file bounds.
Real WordPress runtime evidence is recorded separately from WordPress-light
unit coverage; a development snapshot is not production-package certification.

Code rollback removes these new tools but does not undo completed WordPress
edits. Inspect active execution claims before rollback; restore intended menu
or field values through native administration where needed. No new schema or
data migration is required. Release, tag and publication remain owner-gated.
