# Agent Skills discovery assessment for 0.9.0

Status: research complete; public endpoint not implemented. This is the conditional decision for [#548](https://github.com/mehul0810/aculect-ai-companion/issues/548), not a claim of Agent Readiness scanner support.

The [Cloudflare Agent Skills Discovery RFC](https://github.com/cloudflare/agent-skills-discovery-rfc/blob/main/README.md) is a draft at version 0.2.0. It changed the well-known path and index schema incompatibly from 0.1.0. Its index is a directory of actual Agent Skills artifacts: each entry points to a `SKILL.md` or archive and carries the SHA-256 digest of those exact bytes. A generic list of MCP capability families is not an Agent Skills index under this draft. The authenticated MCP `tools/list` and capability directory are also not safe substitutes for a public index because they vary by user, scopes, site configuration, and enabled tools.

Aculect does not yet package a reviewed, public, site-independent set of Agent Skills artifacts for this discovery purpose. Publishing fabricated `SKILL.md` entries solely to gain a scanner mark would misrepresent conditional OAuth-backed capabilities, create a public instruction supply-chain surface, and add a rewrite/caching contract for a still-changing draft. Therefore, 0.9.0 should not expose `/.well-known/agent-skills/index.json` merely as a capability-family advertisement. The Agent Readiness diagnostics in [#549](https://github.com/mehul0810/aculect-ai-companion/issues/549) should describe this as not implemented or experimental, not a failed authenticated tool catalog.

If the draft stabilizes and genuine public skills are authored, the smallest viable implementation would: ship a short allowlisted set of reviewed `SKILL.md` assets; say that connection through MCP OAuth and the site's permissions are required for authoritative availability and execution; emit only those exact assets in the index with verified digests; fail closed for invalid extensions; serve bounded public responses with tested CORS/cache/rewrite behavior; and prove the packaged endpoint without revealing site/user/client state. This would be a separate reviewed implementation, not a dynamic export of `tools/list`.

This assessment does not remove #548 from the owner-selected 0.9.0 milestone. Closing it as a research-backed no-ship decision or requiring a real implementation is a release-scope decision, not something the pilot can silently treat as complete.
