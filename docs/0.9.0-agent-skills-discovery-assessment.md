# Agent Skills discovery assessment for 0.9.0

Status: private, schema-neutral foundation under local validation; public endpoint deferred to 1.0.0 by owner direction. This is not a claim of Agent Readiness scanner support.

The [Cloudflare Agent Skills Discovery RFC](https://github.com/cloudflare/agent-skills-discovery-rfc/blob/main/README.md) is a draft at version 0.2.0. It changed the well-known path and index schema incompatibly from 0.1.0. Its index is a directory of actual Agent Skills artifacts: each entry points to a `SKILL.md` or archive and carries the SHA-256 digest of those exact bytes. A generic list of MCP capability families is not an Agent Skills index under this draft. The authenticated MCP `tools/list` and capability directory are also not safe substitutes for a public index because they vary by user, scopes, site configuration, and enabled tools.

The separate [Skills over MCP extension](https://github.com/modelcontextprotocol/ext-skills/blob/main/specification/stable/skills.mdx) is stable. It defines negotiated, authenticated `skills/list` and `skills/get` methods and `skill://` resource reads for compatible clients. That wire contract informs the runtime work in [#538](https://github.com/mehul0810/aculect-ai-companion/issues/538); it does not make the draft public `.well-known` index stable or permit custom/site-specific skill content to be published there.

The branch now packages three core `SKILL.md` files for authenticated, connection-filtered MCP discovery. They have not been approved as public, unauthenticated artifacts, and their availability depends on the site's tool policy. Publishing fabricated or conditional entries solely to gain a scanner mark would misrepresent OAuth-backed capabilities, create a public instruction supply-chain surface, and add a rewrite/caching contract for a still-changing draft. Therefore, 0.9.0 should not expose `/.well-known/agent-skills/index.json` merely as a capability-family advertisement. The Agent Readiness diagnostics in [#549](https://github.com/mehul0810/aculect-ai-companion/issues/549) should describe this as not implemented or experimental, not a failed authenticated tool catalog.

If the draft stabilizes and genuine public skills are authored, the smallest viable implementation would: ship a short allowlisted set of reviewed `SKILL.md` assets; say that connection through MCP OAuth and the site's permissions are required for authoritative availability and execution; emit only those exact assets in the index with verified digests; fail closed for invalid extensions; serve bounded public responses with tested CORS/cache/rewrite behavior; and prove the packaged endpoint without revealing site/user/client state. This would be a separate reviewed implementation, not a dynamic export of `tools/list`.

For 0.9.0, `AgentSkillsDiscoveryCatalog` is an internal adapter over the existing packaged-core Skills provider. It returns exact document bytes, SHA-256, and byte count only for an explicit bundled-ID allowlist; its default is empty. It does not read custom, plugin, site, user, or connection-specific Skills. No public route, index schema, cache policy, or scan-facing claim is registered. Focused tests verify exact-byte digests and fail-closed selection; packaged-artifact and independent review remain to be completed.

The broader public index and its wire-format, publication, cache, and host checks are deferred to 1.0.0. This foundation alone does not close [#548](https://github.com/mehul0810/aculect-ai-companion/issues/548) or turn a public-readiness diagnostic green.
