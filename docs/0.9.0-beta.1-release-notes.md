# Aculect AI Companion 0.9.0 Beta 1

Status: unpublished draft for the intended `0.9.0-beta.1` tag. Plugin and package metadata remain `0.9.0`, following the existing prerelease convention. A publication date has not been selected.

## Tester scope

This candidate adds opt-in MCP Apps presentation alongside the existing MCP tools and normal text responses. The Apps include read-only site information, post-update revision review, pattern selection, and media/content reference pickers. Pickers send a selected reference to the assistant. Applying a layout, inserting media, or updating content requires a separate authorized action.

Negotiated post updates can request an exact-operation decision from the authenticated WordPress user. Approval records the decision; the assistant must resubmit the same request before execution. Image upload opens the site's WordPress-authenticated page for a human to choose and upload a file, then return its attachment ID to the assistant.

MCP Apps are disabled by default. Site administrators can turn on **Enable MCP Apps** in **Settings > AI Companion > Advanced**, then select **Save Advanced Settings**. Reconnect the assistant after enabling the setting so it can refresh its supported features. Disabling the setting stops Apps presentation on subsequent requests while retaining ordinary text responses.

The preference is included in settings export/import and returns to off when settings are reset. Existing exports without the preference leave it unchanged. Site code can still override the saved preference with the `aculect_ai_companion_mcp_apps_enabled` filter; Advanced Settings shows a notice when the effective state differs:

```php
add_filter( 'aculect_ai_companion_mcp_apps_enabled', '__return_true' );
```

Use only a test site and a compatible MCP client. Confirm the ordinary text result remains available to clients that do not support MCP Apps. Turn off the setting and remove any enabling filter when not testing.

## Skills and imports

The three packaged core Skills and site-local custom Skills provide authenticated MCP guidance. They do not execute tools or grant permissions. Only administrators can manage custom Skills. Imported Skills remain disabled until an administrator reviews and enables them. The public Skills Index is deferred to 1.0.0.

## Testing focus

Install the candidate ZIP on a disposable WordPress test site and retain a database/files backup before replacing an existing installation. Check normal text-only operation first, then opt in to MCP Apps and exercise selection, post-update review, approval/decline, and image-upload handoffs. Confirm selected references alone leave content unchanged. Test custom Skill creation, import, enable/disable, and removal with an administrator account, and confirm an unauthorized role cannot manage them.

Report the candidate tag or ZIP checksum, WordPress/PHP version, AI client and device, steps, expected result, and observed result. Remove credentials, cookies, tokens, and private content from reports.

## Known gaps and limits

- Real ChatGPT web and mobile rendering, and rendering on other MCP hosts, have not been proven.
- Cloudflare-dependent behavior and edge-challenge handling remain unverified; this beta does not claim to bypass Cloudflare challenges.
- Indexed search on SQLite has not been verified.
- For this first beta, the owner selected real-site and ChatGPT web/mobile testing after the package is available. Those checks remain unverified under [#374](https://github.com/mehul0810/aculect-ai-companion/issues/374); local fixture results do not establish host compatibility. The issue remains open, and no production-use recommendation is made.
- Tag creation and publication still require exact owner approval; this document is an unpublished draft.
