# Aculect AI Companion 0.9.0 Beta 2 preparation

Status: candidate preparation, unpublished. Plugin/package metadata remain `0.9.0`; the intended tag is `0.9.0-beta.2`. Publication requires separate approval after the remaining gates are resolved.

## Changes since Beta 1

- MCP Apps can be enabled in **Settings > AI Companion > Advanced**. They remain off by default, with text responses available to clients without Apps support.
- Pending post-update approvals show proposed changes. Completion fields and completed-action links are withheld for pending or inconsistent results. Approval records a decision; the same request must be resubmitted before execution.
- Agent Readiness distinguishes saved/effective feature settings, observed request negotiation, text fallback, public WebMCP delivery, and unverified client rendering. Existing opt-in diagnostic logging records bounded capability observations without request contents or credentials.
- A read-only Site Audit App presents existing findings with severity, evidence, recommended read tools and next steps. The text fallback carries the same guidance. Configured URLs and cached update counts do not establish connectivity or current update status.
- Core Skills and the custom template explain purpose, tools, evidence and confirmation. Custom Skill saves/imports show current and proposed guidance, references and dependencies before writing. Replacement is bound to the reviewed version/digest; imports remain disabled until separately enabled.
- Cloudflare detection is separate from successful connection verification. Public probes and missing headers do not certify compatibility.
- Playwright is updated to 1.64.1 for development checks. Its Node >=20 requirement fits the existing Node 24 install/build and Node 20 hosted fixtures. WordPress/PHP requirements are unchanged.

Public WebMCP retains its existing bounded, anonymous public-page context tool. This preparation surfaces its diagnostic evidence; it adds no authenticated management or write tools. MCP Adapter migration is outside this work.

## Candidate checks and remaining gates

The evidence report for the prepared commit/ZIP must name actual results and preserve first failures. Unit adapters, native gateway checks, browser/host rendering and end-to-end OAuth are separate evidence scopes.

| Gate | Required evidence |
| --- | --- |
| Approval lifecycle | Exact installed ZIP: pending and approve make no write; exact resubmit writes once; replay preserves later human edits; decline, changed arguments and stale content cannot apply an old approval. |
| Capabilities and fallback | Enabled/disabled site setting, negotiated/unnegotiated client, resource authorization, text output and no credential/request-content logging. |
| Skills | Review before write, version/digest conflict handling, disabled import/replacement, authorized management and guidance-only behavior. |
| Public WebMCP | Existing bounded/anonymous contract plus native browser and installed-package evidence. Server observation alone is insufficient. |
| Dependencies and package | Current Composer audit, complete development audit inventory, runtime audit, dependency tree, canonical ZIP verification and clean-revision preflight. |
| Compatibility and OAuth | Current exact-package hosted OAuth and supported WordPress/PHP/database matrix. Local OAuth testing remains stopped. |
| Host/UI/performance | Current host rendering, responsive/accessibility checks and comparable declared-fixture timings. Earlier Beta 1 testing deferrals do not apply automatically. |
| Cloudflare | Owner-run connection lifecycle on the intended hostname with real protections enabled; redacted edge/origin evidence for blocked stages. |

Local rendered/browser, VoiceOver/narration and OAuth testing remain excluded by existing owner directions, not passed. Real ChatGPT web/mobile, other-host, Cloudflare and indexed SQLite search evidence remains outstanding. No technical release-ready or production-use recommendation follows from preparation alone.
